왜 JSON으로 나눴나

수집기가 DB 구조를 몰라도 됩니다. 수집 방식이 바뀌어도 백엔드는 JSON 형식만 맞으면 됩니다.

왜 SQLite인가

파일 하나라 설치가 필요 없고, FTS5로 별도 검색엔진 없이 한국어 부분 검색이 됩니다.

4번과의 경계

알림은 subscriptions 테이블을 읽어서 보냅니다. 백엔드는 구독 CRUD까지만 책임집니다.

BE/app/db.py · ARTICLE_SEARCH_SCHEMA
CREATE VIRTUAL TABLE articles_fts USING fts5(
    title, summary, content, author,
    content='articles', content_rowid='id',
    tokenize='trigram'
);

-- 글이 추가·수정·삭제되면 색인도 같이 바뀐다
CREATE TRIGGER articles_fts_insert
AFTER INSERT ON articles BEGIN
    INSERT INTO articles_fts (rowid, title, summary, content, author)
    VALUES (new.id, new.title, new.summary, new.content, new.author);
END;
-- ... UPDATE, DELETE 트리거도 같은 방식

-- 기존 글도 마이그레이션 시점에 한 번에 색인
INSERT INTO articles_fts (articles_fts) VALUES ('rebuild');
trigram이란?
글자를 3개씩 잘라 색인합니다. "쿠버네티스" → 쿠버네 · 버네티 · 네티스. 그래서 "버네티"로도 찾힙니다.
  • 형태소 분석기 없이 한국어·영어 모두 동작
  • 대소문자 구분 없음 (kafka = Kafka)
  • 원본은 articles에 두고 색인만 따로 (external content)

검색 ② · search.py

단어 길이에 따라 색인과 LIKE를 나눠 씁니다

BE/app/search.py
terms = split_terms(query.q)   # 공백 분리·중복 제거·최대 10개
fts_terms  = [t for t in terms if len(t) >= 3]
like_terms = [t for t in terms if len(t) < 3]

if fts_terms:   # 모든 단어 AND
    # bm25 가중치: 제목 10 · 요약 3 · 본문 1 · 작성자 2
    joins.append("... bm25(articles_fts, 10.0, 3.0, 1.0, 2.0)"
                 " ... WHERE articles_fts MATCH ?")
    values.append(" AND ".join(
        _fts_phrase(t) for t in fts_terms))

for term in like_terms:   # 1~2글자는 trigram 불가
    clauses.append("(a.title LIKE ? ESCAPE '\\' OR ...)")

def _fts_phrase(term):   # AND, *, - 를 글자로 취급
    return '"' + term.replace('"', '""') + '"'

auth.py · security.py

비밀번호와 토큰은 원문을 저장하지 않습니다

# 비밀번호: scrypt + 랜덤 salt
# (Flask 시절 werkzeug 해시와 호환)
def hash_password(password):
    salt = "".join(secrets.choice(SALT_CHARS)
                   for _ in range(16))
    digest = _scrypt(password, salt, N, R, P)
    return f"scrypt:{N}:{R}:{P}${salt}${digest}"

# 토큰: 사용자에겐 원문, DB엔 SHA-256 해시만
def issue_token(database_path, user_id, ttl):
    token = secrets.token_urlsafe(32)
    db.execute("INSERT INTO auth_tokens"
               " (user_id, token_hash, expires_at) ...",
               (user_id, _token_hash(token), expires_at))
    return token, expires_at

토큰 유효 기간
5회
5분 내 실패 허용
  • 로그인 실패가 넘치면 429 + Retry-After
  • 실패 횟수 키는 sha256(이메일+IP) → 개인정보 원문 미저장
  • 비밀번호를 바꾸면 기존 토큰 전부 폐기
  • 비밀번호 찾기·이메일 인증 토큰은 1회용

확장성

SQLite로 충분한가

파일 하나라 서버 여러 대로 늘리기 어렵습니다. 지금 규모에선 충분하지만, PostgreSQL로 옮기면 FTS5 검색 부분은 다시 짜야 합니다.

검색 품질

trigram의 한계

오타나 유의어("k8s" ↔ "쿠버네티스")는 못 찾습니다. 색인 크기가 본문보다 커질 수 있습니다.

API 형식

active·email_verified가 1/0

요청은 true/false, 응답은 1/0입니다. 프론트와 맞추려면 응답도 boolean으로 바꿀지 정해야 합니다.

연동

회사명 정확히 일치

company 필터는 정확히 같아야 합니다. 3번이 회사명을 안 주면 블로그 이름으로 대신 저장됩니다.
